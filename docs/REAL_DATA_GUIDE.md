# 非エンジニア向け — サーバーの実データをダッシュボードに表示するまで

対象: **VS Code をデータの入ったサーバーに接続済み**で、コーディングは Claude（AI）に任せたい方。
キーボード操作は「コピー＆ペーストして Enter」ができれば大丈夫です。

## 全体の流れ（5 段階）

1. VS Code に Claude Code（AI）を入れる
2. ダッシュボードのコードをサーバーに置く
3. まずサンプルデータのまま動かして画面を見る
4. Claude に「データのありか調査 → 1ページずつ実データに差し替え」を頼む
5. 確認して保存（コミット）→ いつでも見られるように公開

> このダッシュボードは「データの入り口が 1 か所（`src/lib/data`）」になるよう設計してあるため、
> 画面を作り直す必要はありません。**入り口の中身を実データに差し替えるだけ**で全画面が実数値になります。

---

## 準備知識 — VS Code で使う操作は 3 つだけ

| 操作 | やり方 |
|---|---|
| フォルダーを開く | メニュー「ファイル」→「フォルダーを開く…」 |
| ターミナル（コマンド入力画面）を開く | メニュー「ターミナル」→「新しいターミナル」。コマンドを貼り付けて Enter で実行 |
| Claude と会話する | 左側のアイコン列の Claude マークをクリック → チャット欄に日本語で依頼 |

---

## STEP 1. Claude Code を入れる

1. VS Code 左端の「拡張機能」アイコン（四角が 4 つ並んだマーク）をクリック
2. 検索欄に `Claude Code` と入力 →「インストール」
   - サーバー接続中は「**SSH: … にインストール**」というボタンが出ることがあります。出たらそれも押してください
3. 初回はブラウザが開いてログインを求められます → Claude（Anthropic）のアカウントでログイン

## STEP 2. ダッシュボードのコードをサーバーに置く

ターミナルを開き、次の 1 行を貼り付けて Enter:

    git clone https://github.com/vie324/salon_one_dashboard.git

終わったらメニュー「ファイル」→「フォルダーを開く…」で `salon_one_dashboard` を選んで開き直します。

> エラーが出たら（git や Node.js が入っていない等）、エラー文を**そのまま** Claude のチャットに貼り付けて
> 「このエラーを解決して」と頼めば対処してくれます。

## STEP 3. まずサンプルデータのまま動かす

ターミナルで 1 行ずつ実行:

    npm install
    npm run dev

- 右下に「ポート 3000 …」という通知が出たら「**ブラウザーで開く**」をクリック
- 通知が出ない場合は、画面下部の「**ポート**」タブ → `3000` の行の地球アイコンをクリック
- ダッシュボードが表示されれば準備完了です（この時点の数値はまだ架空のサンプル）
- 止めたいときは、ターミナルをクリックして `Ctrl + C`

## STEP 4. Claude にデータのありかを調べてもらう

Claude のチャット欄に以下をコピペします（`◯◯` はわかる範囲で書き換え。わからなければ消さずそのままでも OK）:

    このサーバーにはサロンの売上・顧客・予約などの実データが保存されています。
    どこに・どんな形式（データベース／CSV／Excel など）で入っているか調査して、
    非エンジニアにもわかる言葉で報告してください。
    心当たり: ◯◯（例: /home/salon/data フォルダ、MySQL の salon_db）
    今回は調査だけで、ファイルの変更はしないでください。

報告を読んで「それで合っている／そのフォルダではなくこっち」と返せば、認識合わせができます。

## STEP 5. まずトップページだけ実データに差し替える

一度に全部やらせず、**1 ページずつ**が失敗しないコツです。まずトップページから:

    このダッシュボードは src/lib/data/index.ts の関数（セレクター）がデータの唯一の入り口で、
    今はサンプルデータを返しています。先ほど調査した実データを使って、
    まずトップページ用の getOverview と getAlerts だけを実データに差し替えてください。
    条件:
    - 戻り値の型（src/lib/types.ts）は変えない
    - パスワード等の接続情報はコードに直接書かず .env.local に保存し、Git に含めない
    - データベースには読み取り専用で接続する（書き込み・削除は絶対にしない）
    - 実データに存在しない項目は、架空の数字で埋めず「データなし」とわかる表示にする
    - 終わったら npm run build が通ることを確認し、変更内容を平易な言葉で説明する

終わったらブラウザ（localhost:3000）を再読み込みして、実際の数字と合っているか確認します。
おかしいところは日本語でそのまま指摘すれば直してくれます。例:

    客単価が 0 円になっています。売上÷客数で出るはずなので直してください。

トップページが正しくなったら、同じ要領で 1 ページずつ進めます:

    次は /sales（売上・実績）ページを実データに差し替えてください。条件は前回と同じです。

以降 `/customers` `/cashflow` `/financials` … と、よく見るページから順に。
実データが無いページ（例: 在庫データを取っていない等）は「このページはサンプルのままでいい」と伝えれば OK です。

## STEP 6. 保存する（コミット・プッシュ）

区切りがついたら Claude に:

    ここまでの変更を、内容がわかるメッセージでコミットして GitHub にプッシュしてください。

これで作業内容が GitHub に記録され、サーバーが壊れても復元できます。

## STEP 7. いつでも見られるように公開する

実データが**このサーバーの中**にあるため、同じサーバーで動かし続けるのが簡単・安全です:

    このダッシュボードをこのサーバーで常時起動させてください。
    npm run build で本番ビルドし、サーバーを再起動しても自動で立ち上がるようにして、
    社内から http://（サーバーのアドレス）:3000 で見られるようにしてください。

- Vercel などの外部サービスに置く方法もありますが、サーバー内のデータへ外から届く仕組みが別途必要になり、
  売上データを外部に出すことにもなるため、まずはサーバー内での閲覧をおすすめします
- 見られる人を制限したい場合は「**ログイン（パスワード）を付けて**」と Claude に頼んでください

---

## 困ったときの 5 か条

1. **エラーは読まなくていい** — そのままコピーして Claude に貼り「このエラーを解決して」
2. **一度に頼まない** — 1 ページずつ、1 機能ずつ。大きい依頼ほど失敗しやすい
3. **画面の不具合は日本語でそのまま伝える** — 「グラフが表示されない」「先月の数字が出ない」で通じます
4. **壊れた気がしたら** — 「直前の変更を元に戻して」。Git が履歴を持っているので戻せます
5. **大事な作業の前に** — 「今の状態をコミットして」と一言。セーブポイントになります

## 安全のための約束（Claude への依頼文に入っている理由）

- **読み取り専用で接続**: ダッシュボードは「見る」だけの道具。元の売上データを書き換える事故を防ぎます
- **パスワードは `.env.local` へ**: 接続情報をコードに書くと GitHub に上がってしまうため、Git 管理外のファイルに分離します
- **型（`src/lib/types.ts`）を変えない**: 画面とデータの「契約書」。守っている限り全画面が壊れません
